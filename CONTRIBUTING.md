# Contribuir a UCHINO

1. Crea una rama con un nombre descriptivo.
2. Explica en el pull request qué cambiaste y cómo lo verificaste.
3. No subas `.env`, claves, contraseñas, modelos pesados ni datos personales.
4. Ejecuta el build de la interfaz y las pruebas del módulo que modificaste.
5. Si el cambio afecta la operación, actualiza `docs/GUIA_PUBLICA.md`.

Para cambios de voz, ROS2 o hardware, indica qué parte fue observada realmente y qué parte queda pendiente de equipo físico.
